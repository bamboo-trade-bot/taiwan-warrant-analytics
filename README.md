# 台股權證隱波分析

抓取證交所與櫃買中心的權證公開資料，自行反解隱含波動率與 Greeks，
再把同標的、同天期的權證擺在一起比價。

交易所不提供隱含波動率——但反解所需的原料（權證價、標的價、履約價、
行使比例、到期日）全都是公開資料，所以自己算得出來。自己算的好處是
跨發行商用的是同一套基準，不必相信任何一家券商網站的數字。

## 資料來源

全部免費、免登入、無速率限制，屬政府資料開放授權（標示來源可商用）。

| 端點 | 內容 |
|---|---|
| `openapi.twse.com.tw/v1/opendata/t187ap37_L` | 上市權證基本資料彙總表（履約價、行使比例、到期日、上下限價、發行量） |
| `twse.com.tw/rwd/zh/afterTrading/MI_INDEX?type=0999…` | 上市每日收盤行情，六個權證分類，可回溯歷史 |
| `tpex.org.tw/openapi/v1/tpex_warrant_issue` | 上櫃權證發行基本資料（含流通在外） |
| `tpex.org.tw/openapi/v1/tpex_warrant_daily_quts` | 上櫃每日行情 |

MI_INDEX 的六個權證分類代碼：`0999` 認購、`0999P` 認售、`0999C` 牛證、
`0999B` 熊證、`0999X` 可展延牛證、`0999Y` 可展延熊證。

## 用法

只需要 Python 3.10+，沒有任何外部套件（純標準函式庫）。

```bash
python main.py                          # 自動抓最近一個交易日，約 3 分鐘
python main.py --date 20260918          # 指定交易日
python main.py --date 20260918 --skip-fetch   # 只重算指標
python export_web.py --out docs/data.js # 產生網頁資料（省略 --date 用庫裡最新那天）
```

省略 `--date` 時會從今天往回探，找到第一個有權證收盤行情的日子。週末、
國定假日、或執行時間早於資料上線，都會自動退到正確的交易日。

`docs/index.html` 是靜態頁面，和 `docs/data.js` 放在一起就能直接開。

## 線上版

https://bamboo-trade-bot.github.io/taiwan-warrant-analytics/

由 `.github/workflows/daily.yml` 每個交易日台北時間 18:00 自動更新，
也可以在 Actions 頁面手動觸發。

流程是：從 release 取回累積的 `warrant.db` → 抓當日資料併入 → 產生
`docs/data.js` → 部署到 Pages → 把資料庫存回 release。

**資料庫和網頁資料都不進版控。** 兩者都是每天重產的衍生物，逐日提交
一年會讓 repo 長好幾 GB。資料庫改存在固定 tag `warrant-db` 的 release
裡，網頁資料則直接進 Pages 部署產物。repo 本身只留原始碼。

## 計算上的幾個重點

**行使比例必須先除掉。** 台股權證報價是「一單位權證」的價格，而一單位
只能換到 `ratio` 股標的，所以 `權證價 = 行使比例 × BS理論價`。反解 IV
前沒有先除以行使比例，算出來的隱波會完全錯誤。這是最容易踩的坑。

**牛熊證與上下限型排除。** 那是障礙式選擇權，觸及上下限即結算，用
Black-Scholes 計價會系統性高估其價值，算出來的 IV 沒有意義。

**優先採用買賣中價而非收盤價。** 大量權證整天零成交，收盤價是空的；
造市商掛出的買賣中價才是當下能成交的真實價格。

**基本資料的出表日會晚於交易日。** `t187ap37_L` 週六照樣出表，所以
`snapshot_date` 可能大於最後交易日。join 時優先取「交易日當下已知」的
快照（回測才不會用到未來資訊），找不到才退回最早一份。

## 資料品質

以 2026-09-18 收盤為例：

- 基本資料 50,744 筆（上市 40,276 + 上櫃 10,468）
- 每日行情 44,299 筆，其中 9,910 筆的買賣報價由 MIS 補齊
- 算出指標 44,235 檔，其中 37,391 檔解得出 IV（85%）
- 匯出上線 36,054 檔 / 842 個標的

解不出 IV 的 6,844 檔幾乎都是「當天完全沒有買賣報價也沒成交」。這不是
計算失敗，而是造市商根本沒掛單——這檔你買不到。程式保留 NULL 而不是硬塞
數字，這個欄位本身就是警示訊號。

## 上市與上櫃的資料落差

櫃買中心的 OpenAPI **完全不揭露買賣報價**——10,468 筆上櫃行情裡，買價與
賣價全部是空的；上市則有 31,076 筆有買價。

用收盤價代替買賣中價會產生誤導：收盤價是當天最後一筆成交，可能發生在
早上，而標的收盤價是下午的，兩者時點對不起來，依此排序會排出假的便宜貨。

解法是 `mis.py`——證交所 MIS 有上櫃權證的五檔報價，收盤後掃一輪即可補齊。
實測 10,468 檔裡補到 9,910 檔（94.7%），上櫃因而有了真實的買賣中價與
價差比，解不出 IV 的檔數也從 10,698 降到 6,844。

效果很具體：8227 巨有科技隱波最低的那檔價差比是 **55.25%**，補齊之前它會
排在第一名而且毫無警示。

還有兩個一樣會靜默吃掉整個上櫃市場的坑：匯出時不要用「必須有買賣中價」
當過濾條件（曾因此少掉 5,122 檔權證、266 個標的），以及上市與上櫃的基本
資料出表日不同，join 時不能寫死單一 `snapshot_date`。

## 備註欄的解析

證交所沒有給上市權證的流通在外欄位，而是把註銷紀錄寫成中文句子塞在備註裡：

    ◎2026/05/21申請自行註銷權證1,900仟單位，剩餘權證3,100仟單位。
    ◎2026/06/11標的證券除息，調整後履約價格1,855.05元，調整後行使比例0.0190。

`notes.py` 把它變回數字。40,276 檔上市權證的流通在外可填補 98.1%：

| 來源 | 檔數 | 說明 |
|---|---|---|
| `NOTE_LEFT` | 21,337 | 交易所自己載明剩餘量，直接採用 |
| `ISSUED` | 18,157 | 從未註銷也未增額，流通量即發行量 |
| `NOTE_CALC` | 14 | 只給註銷量且確定無增額，才自行相減 |
| 未填 | 768 | 判斷不了，保持 NULL |

同時抽出 26,620 筆履約價調整事件，存進 `warrant_adjustment` 表。這是把
歷史隱波算回去的前提——要算某檔三個月前的隱波，就得知道當時的履約價。

解析自由文字的三個教訓：

* **換行會切斷句子。** 備註是給人看的排版文字，同一句可能跨行，按行切
  會漏掉一大半。先把空白與換行全部去掉再比對。
* **句型不只一種。** 註銷有「載明剩餘量」和「只給註銷量」兩式，另有
  「增額上市」會讓流通量增加，除權息調整也有新舊兩種措辭。
* **寧可留 NULL 也不要猜。** 只在能交叉驗證（剩餘量落在 0 到發行量之間）
  時才填值，對不上就放棄那一檔。

流通在外與報價品質的關係沒有想像中乾淨。剩餘比例 >50% 的價差比中位數
1.67%、15–50% 是 2.74%、5–15% 是 3.77%，但 <=5% 反而回到 2.48%——方向
對但不單調，所以這欄是參考資訊，不宜當硬性篩選條件。

## 已知缺口

交易所端沒有歷史：`t187ap37_L` 與櫃買的發行資料都只有當日快照，目前庫裡
只有一天。每日排程會一天一天累積，但在那之前無法回答「這家券商是不是
一路把隱波往上調」。

歷史其實補得回來。備註欄就是一份帶日期的變更日誌——24,526 檔記錄了
履約價與行使比例的調整（多為除權息所致），據此可以往回重建任一天的正確
履約價，再配上 MI_INDEX 能回溯的歷史行情，就能算出過去的隱波。同一段
文字裡的「剩餘權證 X 仟單位」也就是流通在外。

**資料庫會持續長大。** 基本資料已經做了異動去重（一天通常只有數百列，
而非五萬列），但行情與指標每天各約 4.4 萬列，粗估每日增加 8 MB 左右。
一年後會接近 GitHub release 單檔 2 GB 的上限，屆時需要改成分年切檔、
或把久遠的每日行情彙總成週/月資料。

本專案為資料分析工具，不構成投資建議。權證為高槓桿商品，時間價值每日
